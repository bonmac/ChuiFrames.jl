### p4-groupby tasks (phase A)

1. `typed_keys`, `keyhash`, `KeyTable` (`getorinsert!`, `lookup`, `length`, `keyvalues`) with the
   exact signatures of spec §2.2. Canonicalisation tests: ±0, NaN payloads, `missing`, `DictColumn`
   with ±0 entries (`codes = true` and `false`), Tuple keys, cross-type `lookup` (`Int` against
   `Float64`).
2. `radix_partition` (spec §2.4 signature, stable), plus a property test (stability, permutation).

### p4-groupby2 tasks (phase B)

3. `build_gindex` on the typed keys (eager `group_by` gets faster; all existing tests pass); the
   `n=10` budget row (ADR-0022 rule 3).
4. Eager grouped `summarise`: unchanged per-group Base calls over the new index, bitwise equal to
   phase 3 (`===` test). Simple-aggregate recogniser (spec §2.1, via `_aggregator`). Typed
   accumulators (`add_sum` type) with the `Vector{Any}` fallback for MapM/ReduceM. Accumulator
   vs protocol unit tests on `Int8`, `Int32`, `Bool` and `Float32` (exact or within tolerance,
   spec §2.3).
5. Lazy hash-aggregate sink. `p4-groupby2` **restructures the morsel loop in `execute.jl`** (it
   cannot sit behind `run_rest`, reviewer M6), and every morsel still goes through
   `_runstage(ph, f, kernel)`. Steps: partial per contiguous range → global dictionary remap for
   `DictColumn` keys → merge in `(range, seq)` order (mixed radix modes) → final → sort by keys.
   Includes the adaptive radix switch (`_FORCE_RADIX_SWITCH`, forced at 4 groups in tests), the
   raw first-seen key, `drop = false` levels, and the `explain` lines in `_explain_rest`. Updates
   `lazy_tests.jl` and `test/snapshots/lazy/**` for the new text.
6. Grouped-window sink (parallel over contiguous group ranges via `apply(::MutateStep)` on
   sub-frames, scatter, eager element types).
7. lazy == eager property tests for grouped sinks at `-t 1` / `-t 4`, including a Source with
   permuted per-partition dictionaries.

### p4-join tasks (phase B, after ★ K1–K3)

0. Apply the ★ answers. K1 replaces the placeholder `on_by` with the chosen keyword in code, tests
   and docs, and in `docs/research/parity-dplyr.md` (the join rows, the `on =` sketch at the "Plain
   `==`" item, the suffix divergence). K2 picks spec §1.2 option A or B. K3 sets which parity
   rows ship.
1. `JoinStep` + verbs + key parsing + `JoinNames` (output schema and naming, dplyr facts of spec
   §1.6), eager. DataAPI methods (`innerjoin` … `antijoin`, `crossjoin` if K3 ships it).
   Unit tests on the dplyr examples.
2. Build/probe (`join.jl`) on the frozen `KeyTable`/`radix_partition`: broadcast and partitioned
   (`_FORCE_JOIN`), `na_matches`, `multiple`, the row-local `unmatched` checks, the hidden y-row
   column, and `JoinTailStep` for right/full and the y-side `unmatched` checks.
3. Oracle nested-loop join; differentials against dplyr (Rscript) and DuckDB/Polars (uv); the new
   divergence doc.
4. `JoinNode` (tree, `==`, `fmap`), tree-aware passes, filter pushdown through joins with the
   totality rule and the does-not-fire cases (spec §1.3), and per-side projection that keeps
   clashing columns (spec §1.4).
5. Lowering to `ProbeStep`/`JoinTailStep` (methods `isstreamable`/`_steptotal` in `joins.jl`, no
   `execute.jl` change), `collect`/`reference` on trees, `explain` tree printing (linear plans
   print as before; "not rendered (the stage holds a join probe)"), and goldens in the new
   snapshot directory.
6. lazy == eager property tests for joins at `-t 1` / `-t 4`, each strategy forced.
7. `docs/src/api.md`, `docs/src/lazy.md` for the new exports.

### p4-codegen tasks (phase A)

1. Measure on 1.13 and 1.10: compile time per new shape against depth, per-row interpreter
   against compiled on 1–10-step stages, multi-column and string stages. Write the new research
   doc and set `INTERP_THRESHOLD`.
2. `kernel_decision` (with `est_rows === nothing` meaning compiled only when cached), the
   whitelist, the type check on the probe frame, closure-composed fused kernels with per-call
   typed outputs, no short-circuit, interpreter re-run on any exception, `_KERNEL_DISAGREE`,
   and the shape cache (`typeof(f)` in the shape) behind `_KERNEL_LOCK`.
3. Property test: compiled (forced) == interpreter, exception types (including the cross-step
   `log`/`div` case), empty-morsel types, disagreement counter 0.
4. `_explain_kernel` line under `kernel = true` (`occursin` tests under `withforce`).
